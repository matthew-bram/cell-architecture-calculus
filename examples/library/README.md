# The library: the worked example

A town's public library lends items to its members. This package models its circulation slice on the calculus and carries the whole round trip: a design corpus, the two maps checked by theorem, one design written to the method's tables, the model transcribed from it with every example a theorem, the views generated from the model, a reference implementation tested against those views by example id, and the implementation's trace replayed into the model.

Nothing here is a real library's. The corpus was written for this repository so that every row the model transcribes has a sentence to point at.

## The layout

| Where | What |
| --- | --- |
| [corpus/](corpus/) | The design corpus: the [vision](corpus/vision.md) with the principles, the trust zones and eight journeys each carrying its Steps and References tables; the [capability map](corpus/capability-map.md) with the subdomain kinds and the journey matrix; the [architecture](corpus/architecture.md) with the cells by zone, the three verbs, the paths table and the direction rule |
| [designs/](designs/) | The [circulation design](designs/circulation.md), prose where the meaning is and the method's tables where the model is transcribed from: circulation and notices, fines, pickup, renewals, the borrow journey, its contracts and attributes |
| [JourneyMap.lean](JourneyMap.lean) | The journey map, checked: the cells with their zones, every journey as a DAG of steps, the matrix row equal to the journey's table, composition acyclic and succession cycling by design, journey 2 as a pipeline in `Except`, the paths table and the rule that the stacks never ask the desk |
| [ContextMap.lean](ContextMap.lean) | The context map beside it: each cell a bounded context with its kind, every arrow's relationship upstream to downstream in the standard vocabulary, coverage and translation as theorems |
| [Library/](Library/) | The model. `Architecture`, the principal and the zones; `Circulation`, the two cells with their examples, coverage, traces, wire and sentences; `Journeys`, the borrow journey as a term and the hold shelf's fan-in; `Envelopes`, the actor gate and the run checks; `Inputs`, fines deciding on circulation's answer and the clock; `Policy`, the renewals ladder; `Promises`, the warning within a minute; `Boundaries`, the alias map and the scrub; `Governance`, the review line, the retired example and the upcaster |
| [generated/](generated/) | The two views the build renders from the live examples, Gherkin for a reader and JSON for the tests, each stamped with the model's hash. Regenerated by `lake exe fixtures`, never edited |
| [impl/](impl/) | The reference implementation in Python, its tests consuming the fixtures by id, and the recorder that writes its trace |
| [traces/](traces/) | Seven traces in the wire shape: three that conform, four that the checker rejects, one of each kind of rejection |
| [mutants.json](mutants.json) | Ten deliberate changes to the model that the examples and theorems must notice |

## The commands

From this directory, with Lean's version manager installed once as the repository's README says.

```
lake build                                                   # every theorem checked, no warnings
lake exe fixtures                                            # the views under generated/
python3 ../../tools/review-check.py Library/Governance.lean . # warns: the design is unreviewed
python3 ../../tools/mutants.py mutants.json                  # the gate, 10 of 10
lake exe replay traces/circulation-good.json traces/borrow-run-good.json traces/circulation-recorded.json
lake exe replay traces/circulation-retry-twice.json          # rejected at step 1, as must be
python3 -m unittest discover -s impl -v                      # the implementation against the fixtures
python3 impl/record_trace.py                                 # the implementation's trace, replayed above
```

The review check warns on purpose: the review line is for a person to sign after reading the model against the design, and no one has. Signing it writes the design's hash into `Library/Governance.lean`, and the check fails from then on whenever the design changes under a signed line.

## What to read first

The [vision's journey 2](corpus/vision.md#journey-2-borrow-an-item), then its row in [JourneyMap.lean](JourneyMap.lean) with the theorems that check it, then the [design's Commands and Decide tables](designs/circulation.md#commands), then [Library/Circulation.lean](Library/Circulation.lean), where each row is one constructor, one branch or one example, and the generated [feature file](generated/circulation.feature), which is the examples as a reviewer reads them.
